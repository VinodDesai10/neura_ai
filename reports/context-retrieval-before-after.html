🔧 Changes Made

RC1 — Qdrant userId filter
Files: qdrant-client.js · vector-memory-store.js

queryQdrantPoints() now accepts userId. When present, applies a Qdrant keyword filter: { must: [{ key: 'userId', match: { value: userId } }] }. Scopes vector search to the current user's memories, eliminating cross-user noise while preserving cross-session recall for the same user. The userId payload index is created in ensureQdrantReady(). A graceful fallback retries without the filter if the index doesn't exist yet on an older collection.

RC2 — Factual memory vector scores
Files: factual-memory-store.js · candidateFetcher.js

factualMemoryStore.findRelevant() accepts a new queryEmbedding parameter. When a stored embedding exists in the Postgres embedding column, cosine similarity is computed and used as vectorScore — previously hardcoded to 0. This gives factual memories access to the 40% vector weight in the hybrid scoring formula. candidateFetcher.js passes the pre-computed query embedding through. A one-time backfill script (tools/backfill-factual-embeddings.js) generated and stored embeddings for the 90 seeded factual memories.

RC3 — Postgres relevance gate
Files: factual-memory-store.js

SQL now orders by ts_rank DESC, importance DESC (FTS relevance first). The passes filter was tightened: a factual memory now requires lexicalScore > 0 OR vectorScore > 0.15 OR importance ≥ 0.85 (was importance ≥ 0.65). This stops topically-unrelated high-importance memories from dominating the candidate pool.
